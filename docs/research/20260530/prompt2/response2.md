You're right on all three points, and I went back and verified each one directly in the live apps just now rather than going from memory.

**On deletion — confirmed, and worse than I implied before.** When I select a component node in Archie, the right Inspector panel has no delete control anywhere — I scrolled it all the way down (Code/Details/Metrics/Data tabs → description → Configuration → Economics → a big YAML block → What it is → Gains → Costs → Recommendations → Metrics → Data Context) and there is no Remove button at the end. Same for connectors: clicking the Nginx → Node.js edge opens a "Connection" inspector (Protocol HTTP, Latency, Co-location, Patterns, Endpoint Health, Connection Health) and again no delete button. Deletion *does* work — pressing the Delete key removed both the CDN node and the edge in my tests, and the score recalculated — but it's an undiscoverable keyboard-only action. A solo user who doesn't guess the shortcut literally cannot remove a node or a wrong connection from the screen. The Reference app, by contrast, puts an explicit **Duplicate** and **Remove** button right on every node the moment you select it (I saw these as labeled controls on each block, e.g. its DNS/CDN/App Server nodes). For connectors specifically, Archie has no removal path at all in the visible UI — that's a real functional gap, not just a polish one.

**On information density — your read is correct.** The Reference app keeps a single, calm surface: a left palette of compact type tiles, the canvas, one right-side Budget/Required strip, and a single bottom action. Each node shows just what you need inline (provider, $/mo, replicas) and the per-node deltas live inside one small dropdown. Archie, by comparison, is showing many competing layers at once: the top nav, the full left toolbox where every component is a tall card with IS / GAIN / COST / tags / price, plus the challenge brief panel, five canvas toggles, two scenario dropdowns, per-node metric overlays, the Heatmap Legend, the minimap, the simulation timeline, and the bottom five-axis scoreboard — all visible simultaneously. So the same screen real estate carries far more ink in Archie for the same task.

**The Inspector is the densest offender.** Selecting one component currently dumps four tabs and roughly eight stacked sections into the panel, and the raw YAML/wrangler.toml config block takes over the middle of it — that's the "quickly becoming very confusing" you're describing. The information is good; the problem is that it's all expanded at once with no hierarchy, and the one thing a user most often wants when a node is selected (rename, swap, delete) isn't there.

Concretely, the highest-leverage fixes are: (1) add visible **Remove** (and Duplicate) buttons on node *and* edge selection — the single biggest correctness gap, since connectors can't be deleted from the UI at all today; (2) **collapse the Inspector by default** — show a short header (name, provider/variant, $ · throughput · latency, and the Remove button) with the YAML, Gains/Costs, Recommendations, and Metrics behind collapsed disclosures; and (3) **demote the palette cards** to compact rows (icon + name + price, with the IS/GAIN/COST detail revealed on hover or click) so the toolbox stops competing with the canvas. Those three alone would move Archie much closer to the Reference app's density without giving up any of its (genuinely richer) underlying data.
