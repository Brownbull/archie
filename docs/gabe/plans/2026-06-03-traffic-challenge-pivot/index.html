Traffic Realism + Challenge Difficulty ISAPivot

Generated 2026-06-03 · /gabe-plan · source .kdbp/PLAN.md · decisions D55–D62 · LEDGER "PLAN CREATED: Traffic Realism + Challenge Difficulty (ISAPivot)" · investigation workflow w9vlphjd8

Summary

Make traffic sources first-class configurable objects and use them — plus the dormant simulation levers built by the now-complete "Simulation Realism (E1–E8)" epic — to make challenges genuinely hard.

Why now: E1–E8 shipped the type-specific sim mechanics (cache hit ratio, write/read split, cold start, queue backpressure, …) but challenges can't exercise them. A challenge today = "place the listed blocks + a couple replicas." This epic adds the player-facing surface + difficulty levers.

Key constraint discovered (adversarial verify): challenge scoring is sim-stats-only (uptime / p99 / cost / topology) — it never reads the demand/heatmap/tier layer, which is off in challenge mode. So origin (multi-region) is graded as an architecture requirement in the rubric, not via demand multipliers (which would do nothing).

Unified traffic-source spec

TrafficSource { type : api-client | iot-sensors | mobile-users | web-users (≤4 per challenge, one each) rps : arbitrary, bounded // the "RPS we configure" — replaces discrete tiers kind : steady | realistic | periodic | search // traffic SHAPE (realistic = existing 'wobble') workload : read | write | mixed // NEW — exercises DB write-path / cache (D56) origin : one-region | multi-region // graded as architecture in the rubric (D55) }

Configurable in the right-panel inspector AND on the canvas block (origin shown on the block); authorable on challenges.

Tier digest

All 5 phases are enterprise — each is load-bearing: schema/loader (P0), the just-stabilized RPS mechanism + sensitive canvas layout (P1), simulateTick which every run depends on (P2), pass/fail scoring for all challenges (P3), and unwinnable-challenge risk (P4). No MVP/prototype phases; no per-dim overrides. Full trade-offs in DECISIONS D58–D62.

Decisions (D55–D62)

IDDecision
D55Origin graded as architecture, not deep sim — multi-region requires CDN/multi-region-DB/DNS in the rubric (demand layer is a no-op for challenge scoring).
D56Add read/write/mixed workload axis, separate from the shape kind — it's the lever that exercises the DB write-path/cache.
D57Per-source routing in Phase 2 — replaces flat even-split so the kind/workload mix reaches specific tiers (even-split fallback kept).
